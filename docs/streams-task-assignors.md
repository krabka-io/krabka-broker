# Native Streams task assignors

Kafka 4.4 supports an ordered broker-side `TaskAssignor` registry and group selection via `streams.assignor.name`. The first configured implementation is the default; KIP-1357 only adds reporting of that selection. See the released [GroupCoordinatorConfig](https://github.com/apache/kafka/blob/4.4.0/group-coordinator/src/main/java/org/apache/kafka/coordinator/group/GroupCoordinatorConfig.java#L328-L340) and [registration validation](https://github.com/apache/kafka/blob/4.4.0/group-coordinator/src/main/java/org/apache/kafka/coordinator/group/GroupCoordinatorConfig.java#L819-L876).

Krabka embedders can implement `coordinator::unified::streams::assignor::TaskAssignor` and build a mutable `StreamsGroupConfig`, and register each `Arc<dyn TaskAssignor>` with `streams.task_assignors.register(...)`. Set `BrokerConfig.streams_group = Arc::new(streams)` before starting the broker. The first registered custom implementation becomes the default; group configuration can select another registered name. Duplicate, blank and reserved built-in names fail registration. New unknown group selections fail config validation; if a previously stored selection is unavailable on a node, that node uses its broker default without discarding unrelated overrides, matching the released coordinator. With no extensions registered, the existing sticky algorithm remains the default. Legacy `auto` and `highly_available` settings are aliases for that algorithm, not separate implementations.

The extension receives resolved tasks, stateful subtopologies, standby count and current member/task state. It returns active and standby target maps. Implementations must be deterministic, non-blocking, non-panicking and return valid assignments. Unknown members/tasks, missing or duplicated active tasks, and process-collocated copies are rejected before installing a target. An assignment error retains the old target and leaves the group dirty for retry; it never silently switches algorithms. Selection changes take effect during the next assignment, through the existing revocation/reconciliation path. Describe v1 reports the selected implementation name.

This API is a native Rust embedding interface, not a stable dynamic-library ABI. The stock executable does not load arbitrary JVM classes, native shared libraries or external processes. Kafka's Java `Configurable`/`AutoCloseable` lifecycle and arbitrary JVM plugins are not compatible with this mechanism. Native extension lifetime is owned by `Arc`; startup configuration belongs to the embedding application. Assignment offloading and panic isolation are not provided. Cross-broker deployments must register identical names and behavior on every broker before storing a group override. Released-JVM custom-plugin interoperability has not been executed for this API.
